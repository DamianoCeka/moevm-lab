# IP and release notes

This repository is prepared as a **private-first research project**.

## Before a public release

- keep dated design notes and benchmark artifacts;
- identify which techniques are existing practice and which are genuinely new;
- document contributors and the origin of every major idea;
- review third-party model and runtime licenses;
- remove weights, credentials, private traces and proprietary data;
- choose an open-source, source-available or open-core license deliberately;
- obtain qualified legal advice before public disclosure when patent strategy matters.

This document is project hygiene, not legal advice.

## Suggested staged release

1. Private repository with simulator and experiment log.
2. Public paper/design note describing the problem and reproducible baselines.
3. Open community core after the licensing decision.
4. Separate commercial modules only where they add operational value rather than hiding reproducibility.

All rights are reserved during pre-release. External contributions should not be accepted until a contributor/license policy is selected.
